EDGE CASES in current code:

1.
Main Thread decides shutdown based on:
allQueuesEmpty()

But queue empty does NOT necessarily mean processing complete.

Example:
Worker takes E1 from queue
Queue becomes empty
Worker has not yet saved E1

At this instant:

Queue = empty
Batch = [E1]
Repository = empty

Main sees:

allQueuesEmpty() == true

and starts shutdown.
Fortunately, your shutdown path flushes batches.
So data won't be lost.

But conceptually:
Queue empty ≠ all work completed
Currently relying on shutdown flushing remaining batches.



2.
Suppose new events arrive after:
allQueuesEmpty()
returns true.

Example:
Main sees queues empty
↓
Begins shutdown
↓
Another producer inserts event

That event may never be processed.
Currently this is safe only because:
Main is the only producer
and production finishes before shutdown begins.
Not sustainable for streaming data like userEvents
